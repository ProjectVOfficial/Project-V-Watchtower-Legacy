## Corresponding source for binaries

Public binary releases must provide compliant access to the corresponding source used to build those binaries.

Project V can keep the **release page focused on Windows installers and executables**. A source ZIP does not need to be the visually prominent download.

However, the corresponding source for the exact released build must still be made available in a compliant manner.

A practical Project V release pattern is:

1. publish the Windows installer / MSI / portable executable as release assets;
2. publish the exact corresponding source either:
   - as a source archive attached to the same release, or
   - in a clearly linked public source repository/tag that exactly matches the released binaries;
3. include the AGPL license and applicable upstream notices;
4. identify that the build is modified Project V software;
5. keep the source available for the period required by the applicable license terms.

For the current repository layout, do not describe GitHub's automatically generated tag archives as the application corresponding source unless the actual application source is present in this repository at that tag.
